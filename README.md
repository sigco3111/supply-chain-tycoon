# FLOW CAPITAL · 방치형 공급망 타이쿤

**0.34.0 프로토타입** · 한국어 · PC/모바일 웹 · 원작 2D 경영 게임

[바로 플레이](https://sigco3111.github.io/supply-chain-tycoon/) · [GitHub](https://github.com/sigco3111/supply-chain-tycoon) · [English](README.en.md)

노드를 연결해 원료를 제품으로 만들고, 물류·가격·연구·기업 지분을 운영합니다. 총 **60종** 가운데 **36종은 소비자 판매**, 산업 센서1종은 별도 산업납품입니다. 나머지23종은 원료·중간재입니다. 실물 제조망, 디지털망, 센서망은 구분됩니다. 실제 제조공정이나 투자 조언이 아닌 게임용 압축 경제입니다.

## 1. 처음 시작하기

설치나 계정 없이 플레이 링크를 여세요. 게임 내 화폐 C는 실제 돈이 아닙니다.

1. 공급망에서 **채굴장 → 종이 공장 → 물류창고 → 매장**을 연결하세요. 노드 선택 → 출력 연결 → 도착 노드를 누릅니다.
2. 상품은 운송 후 도착합니다. 첫 매출까지 기다리고, 보유현금과 영업손익을 구분해 보세요. 건설비·연구비는 별도 투자입니다.
3. 막히는 연결선을 눌러 처리량을 늘리세요. 생산능력이 커도 원료·출구·수요가 부족하면 매출이 늘지 않습니다.
4. `+ 노드`에서 상품과 장비를 고르세요. 장비가 같아도 생산상품은 건설할 때 고정됩니다. 기존 공장 상품이 자동으로 바뀌지 않습니다.
5. 시장 탭에서 가격·생산·기업을 비교하고, 연구소를 지어 새 산업을 여세요. 현금을 모두 투자하지 말고 고정비 여유를 남기세요.
6. 설정에서 내보내기로 저장 파일을 백업하세요. 기기·브라우저를 바꾸면 파일 가져오기가 필요합니다.

**시간:** 1배속에서 경제1틱은1초, 60틱은1게임일입니다. 연구·확장 조건은 현실 대기시간이 아니라 누적 경제틱을 봅니다. 가속과 오프라인 정산도 같은 경제틱을 사용합니다.

### 조작과 탐색

- PC: 보드 드래그 이동, 휠 확대/축소, 노드·연결선 선택.
- 모바일: 한 손가락 이동, 두 손가락 확대/축소. `전체 보기`, 미니맵, `목록` 검색으로 설비를 찾으세요.
- 공급망/시장/경쟁/금융C/목표·도움말 탭으로 화면을 바꿉니다. 현재 운영 회사와 도시를 먼저 확인하세요.
- 회사당 최대40노드입니다. 본사 경영 허브 표시는 생산노드 수에 포함하지 않습니다.

## 4. 두 도시와 물류

- 한빛에서 시작합니다. 철원항은45분 이후, 한빛 항만과 진출비12,000C, 추가 예비현금5,000C가 필요합니다.
- 도시 간에는 **같은 상품의 항만 ↔ 항만**만 연결할 수 있습니다. 도시 간 운송은3틱,6C/개입니다. 현지 기본운송비2C/개는 물류 최적화 후1C/개가 됩니다. 디지털 대역폭은1C/개입니다.
- 철원항은 고정비 임대배율1.2입니다. 두 도시의 상품가격·브랜드·소비수요는 따로 관리합니다.
- 센서 부품·조립·산업납품은 현지 전용망입니다. 제조망/디지털망/센서망을 섞지 마세요.
- 내부 운송과 B2B의 도착예약을 함께 계산합니다. 여러 입력의 완충한도는 원료 한 종류가 공간을 독점하는 것을 막습니다.

## 5. 시장·가격·브랜드

시장 탭의 **시장 / 생산 / 기업** 보기에서 도시·상품·기업·관측구간을 고릅니다. 소비자 판매와 B2B·산업납품은 별도 기록입니다. 현재 재고와 관측기간 생산량도 다른 값입니다.

- 최근60틱은 틱별 관측, 최근600틱은 완료한10틱 묶음입니다. 기록이 생기기 전의 과거 매출을 만들어 넣지 않습니다.
- 상품별 직접 투입비는 원료·가공·운송비입니다. 공동고정비를 임의 배부한 상품 순이익이 아닙니다. 수익은 회사 전체 영업손익을 함께 보세요.
- 광고는 회사×상품×도시의 **브랜드 지수0~100**를 높여 판매배분에 영향을 줍니다. 설문 인지도%나 기업끼리 합계100%인 점유율이 아닙니다. 총 소비수요를 늘리지 않습니다.
- 후기 완제품은 고가일수록 실제 구매량이 줄어듭니다. 분수수요는 평균이며 상품·현금은 정수로 움직입니다. 품절 중 수요를 모아두었다가 한꺼번에 팔지 않습니다.
- 신규16종 시장은 첫 해당 연구해금 전 휴면입니다. 전자 산업납품 부품5종은 소비자 수요와 분리된 도시별1개/틱 수요입니다.

## 6. B2B: 다른 회사에서 원료 받기

시장 → 기업 간 공급 데스크에서 판매·자동발주 조건을 설정합니다. 식품·섬유·전자·차량·신규16종을 지원합니다. 기존 목재/종이/가구/포장재/데이터/서비스/센서 계열은 B2B 대상이 아닙니다.

1. 공급사는 실제 출력/물류노드의 판매를 열고 단가·안전재고·출고상한을 정합니다. 내부 운송이 먼저입니다.
2. 구매사는 상품별 공급사1개·출발노드1개·도착노드1개를 고릅니다. 같은 도시이며 해당 원료 소비/판매 경로가 있어야 합니다.
3. 합의단가·실재고·처리량·도착예약공간·구매현금을 확인한 뒤, 출고할 때 대금을 예약합니다.
4. **1틱 후** 상품입고와 공급사 대금수령이 함께 일어납니다. 현재 B2B 운송비는0C입니다.

조건변경은 새 발주만 바꿉니다. 출발한 배송은 원래 조건으로 도착하고 배송 관련 노드는 도착 전 철거할 수 없습니다. 공급중단/도산/지배권 변경에 자동으로 다른 공급사를 고르지 않습니다. 새발주가 멈춘 이유를 확인하고 조건을 다시 저장하세요. B2B는 회사 사이 돈과 재고의 이동이지 무료 생산이나 소비자 매출이 아닙니다.

## 7. 금융과 기업 운영

금융C에서 상장·신주발행·주식거래·자사주 매입소각·공개/협상매수·방어를 운영합니다. 주식은 정수이고 거래수수료는2%입니다. 장내주문은 다음 게임일에 정산하며 매수대금을 예약합니다. 공개매수는 미달 부분체결과 잔액환급이 있을 수 있습니다.

- **50% 초과** 직접지분이 지배권 기준입니다. 정확히50%는 인수가 아닙니다.
- 소수지분에는 자동 배당·운영권·기술공유가 없습니다. 자회사 현금은 본사 현금이 아닙니다.
- 인수대금은 매도주주에게 갑니다. 대상회사의 설비·현금·원장은 별도로 유지합니다.
- 방어 경보와 대응기간, 우호투자/권리계획, 지배권 상실을 확인하세요. 오프라인 복귀 때는 인수 최종판정·파산 등에 기존 안전장치를 적용하지만 영업손실까지 막아주지는 않습니다.
- 인수 전략실의 주가/회수기간 계산은 현재조건 가정입니다. 확률·최적투자·미래수익 보장이 아닙니다.

## 8. 경기 순환

150분부터 **회복 → 호황 → 둔화 → 불황**, 단계600틱(10분), 한 바퀴2,400틱(40분)으로 순환합니다. 경제틱으로 결정되며 재로딩으로 다시 뽑지 않습니다. 늦게 업데이트한 기존 저장은600틱 준비기간이 있습니다.

| 상품군 | 호황 | 불황 |
| --- | --- | --- |
| 필수식품 (신규 쿠키·오믈렛·샌드위치 포함) | 1.05배 | 0.95배 |
| 일반소비·서비스 (신규 섬유 포함) | 1.10배 | 0.90배 |
| 내구·기술 (전자·차량·신규 책상/소파) | 1.20배 | 0.80배 |

회복/둔화는1배입니다. 기존 가구는 일반소비 분류를 유지합니다. 센서·전자부품 산업납품과 B2B 계약단가·가공비·고정비는 이 소비수요 효과에서 제외됩니다. 주가에는 호황1.08/불황0.92를 목표평가가치에 반영하되 일별변화 한도를 유지합니다.

## 9. 계획은 미리 보기, 위임은 실제 운영

### 경기 대응 계획

시장 → 경기 대응 계획에서 회사·도시·상품·기존 생산설비를 골라 `현재대로 / 생산정지 / 목표 출력재고`를 비교합니다. 최대2,400틱을 **복제본**에서 계산합니다. 실제현금·설비·가격은 바꾸지 않습니다. 계산 중 게임이 진행되면 오래된 결과 경고를 보세요. `설정만 저장`은 가정만 저장하고 미래 상태를 적용하지 않습니다.

### 위임 운영

시장 → 위임 운영에서 준비+4경기의 재고밴드, 기존 B2B 보충, 기존 설비/연결선 증설을 설정합니다. **기본OFF**, 대상·비용 검토 후 켭니다. 0.31 계획 가져오기는 초안이며 자동 활성화하지 않습니다.

- 목표재고에 닿으면 생산을 보류하고 하한 이하에서 재가동합니다. 판매·배송·연구·광고·고정비는 계속됩니다.
- 보충 누적예산/60틱당한도, 증설 누적예산/횟수/레벨/처리량을 제한합니다. 증설은60틱 관측과 같은대상300틱 대기를 지킵니다.
- 추가지출 후 최소현금+향후60틱 고정비를 남겨야 합니다. 다른 운영비 때문에 현금이 줄 수 있어 잔고 보장은 아닙니다.
- 새 노드/연결/도시진출/철거/송금/주식거래는 하지 않습니다. 수동 변경·삭제·운영권 상실이면 멈추고 재검토합니다. 새 설비를 자동 포함하지 않습니다.
- 일시정지하면 지정 B2B의 새 발주도 멈춥니다. 해제 후에는 해당 주문이OFF로 남으므로 직접 다시 설정하세요. 사용예산·실행커서는 저장하며 예산을 자동 충전하지 않습니다.

## 10. 저장·슬롯·오프라인

- 브라우저 로컬 저장에 **독립3슬롯**을 사용합니다. 슬롯마다 현금·연구·계획·위임예산·실행커서가 별개입니다.
- 슬롯별 마지막 정산시각부터 실제 경과시간을 계산하며, 다른 슬롯을 플레이한 시간도 부재시간에 들어갑니다. 1회 최대8시간입니다.
- 온라인과 같은 경제틱으로 운영하므로 수익도 손실도 발생합니다. 오프라인은 무료수익 버튼이 아닙니다.
- 저장실패/정산실패에서는 원본과 커서를 보존합니다. 재시도나 탭닫기 후 같은 시간을 중복 정산하지 않도록 검사합니다.
- 여러 탭 중 운영탭 하나만 씁니다. 읽기전용 탭에서는 저장/조작을 막습니다. 쿠키·사이트데이터 삭제, 시크릿모드 종료, 기기변경에는 진행을 잃을 수 있으니 내보내기를 보관하세요.
- 예전 저장을 가져오면 기존자산/계획/예산은 보존하고 새상품은 재고0·수요휴면으로 추가합니다. 없는 과거 생산/판매이력을 만들지 않습니다.

## 11. 0.34 마무리 점검

신규16종을 **두 도시×4경기×일반/위임256조건**에서 측정했습니다. 최종 표는 변경하지 않은13종의0.33 측정값과 가격을 바꾼3종의0.34 재측정48조건을 합쳤습니다. 원료부터 모두 만드는 독립라인, 기본가격, 무경쟁, 물류연구 완료, 충분한 현금과 연구, 정상가동 후599틱의 회사손익입니다. 연구소/광고/연구비·추가진출비는 제외하며 설비투자는 따로 집계했습니다. 다른 경쟁·가격·B2B매입조건에서 수익을 보장하지 않습니다.

| 신규상품 | 기준가격 변경 | 철원항 불황 일반손익 (C/틱) | 변경 이유 |
| --- | --- | --- | --- |
| 치즈 오믈렛 | 190 → 230 | 0.49 → 19.53 | 유지비 대비 수익이 지나치게 낮음 |
| 프린터 | 850 → 1,150 | -43.12 → 16.98 | 일반운영뿐 아니라 위임 후에도 적자 |
| 로봇청소기 | 850 → 1,100 | -39.50 → 10.58 | 일반운영뿐 아니라 위임 후에도 적자 |

**기존44종 레시피/가격, 신규 가공비/투입량/수요/연구비는 변경하지 않았습니다.** 기준가격에서 파생되는 새게임 초기시세·기본판매가·가격상한·기본 B2B 제시가도 함께 바뀝니다. 기존저장 호환을 위해3종의 가격하한(오믈렛114C,프린터/로봇청소기510C)은 유지합니다. 기존저장의 사용자가 정한 가격/도시시세/B2B 합의단가는 자동으로 덮어쓰지 않습니다. 기존가격을 유지하면 새 권장가보다 낮을 수 있으니 가격 화면에서 직접 검토하세요.

프로젝터는 철원항 불황에서 일반 -18.36C/틱이지만 위임재고밴드 적용 +13.10C/틱으로 대응 여지가 있어 그대로 두었습니다. 독립 전품목 제조보다 부품을 공유하거나 B2B로 분업하는 선택도 남깁니다.

측정표와 재현절차: [밸런스 점검](docs/BALANCE_0.34.md). 과거 버전별 값은 [개발기록 부록](docs/DEVELOPMENT_HISTORY.ko.md)에 보관했습니다. 부록의 당시 미구현/예정 문장은 현재 기능표가 아닙니다.

## 12. 검증 범위와 한계

- 정적 웹 프로토타입입니다. 서버계정·클라우드 동기화·멀티플레이·대출·인재·추가도시는 없습니다.
- Chromium/Linux WebKit의 모바일 터치 에뮬레이션을 확인했습니다. **실제 iPhone Safari의 장시간 터치·발열·오디오·저장 지속성은 미검증**입니다.
- 상품/현금 보존, 구매예약, 기존저장 이식, 저장실패 원복, 슬롯전환·정산 재시도,13회사520노드의8시간 정산을 자동 점검했습니다. 실행시간은 장치/환경에 따라 다릅니다.
- 회사당40노드 제한이 있어 모든 상품을 한 회사에 다 만들도록 설계하지 않았습니다. 자회사·부품공유·B2B를 선택하세요.
- 외부 게임의 코드·아트·UI를 복사하지 않았습니다. 라이선스는 별도 지정하지 않았습니다.
